# WFUemolab.github.io

Website of the **Emotional Adaptation and Psychophysiology Lab (Emolab)** at Wake Forest University, directed by Dr. Christian Waugh.
Live at **https://wfuemolab.github.io/**.

It is a plain static site (HTML + CSS + vanilla JavaScript) hosted on GitHub Pages. There is nothing to install or build: edit a file, commit, push, and the site updates within a minute or two.

## Directory structure

```
.
├── index.html               Home: hero, research themes, latest news
├── people.html              People (rendered from Roster/)
├── publications.html        Publications with live search & filters
├── projects.html            Projects (rendered from Projects/)
├── media.html               Substack, podcasts, TV & news, video
│
├── Roster/                  ← one Markdown file per person
│   ├── christian-waugh.md
│   ├── template.md          copy this to add someone (never shown on the site)
│   ├── Alumni/              ← former members (one Markdown file each)
│   └── photos/              headshots for everyone, referenced by `photo:`
│
├── Projects/                ← one folder per project
│   ├── template-project/     copy this folder to add a project (never shown)
│   │   └── info.md
│   └── <project-name>/
│       ├── info.md
│       └── cover.jpg
│
├── data/
│   ├── news.yml             home-page news feed
│   ├── publications.yml     publication list
│   ├── media.yml            media page content
│   ├── substack.json        latest 3 Substack posts — updated daily by GitHub Actions
│   ├── roster.json          auto-generated by GitHub Pages — don't edit
│   └── projects.json        auto-generated by GitHub Pages — don't edit
│
├── assets/
│   ├── css/styles.css       the single stylesheet (design tokens at the top)
│   ├── js/core.js           shared helpers + Markdown/YAML loader
│   ├── js/<page>.js         one script per page
│   └── img/logo.svg         lab logo (header + browser tab icon)
└── _config.yml              GitHub Pages (Jekyll) settings
```

## Editing content

Entries marked `sample: true` are placeholders and show a yellow **Sample** badge. Replace or delete them.

### Add a lab member
1. Copy `Roster/template.md` to `Roster/firstname-lastname.md` (or to `Roster/Alumni/` for a former member).
2. Fill in the front matter. `title` (the person's name) and `role` are required.
   - `role` is one of `PI`, `Postdoc`, `PhD`, `Master`, `Staff`, `Undergrad`, `Former Postdoc`, `Former PhD`, `Former Master`, `Former Staff`, `Former Undergrad`.
   - When someone leaves the lab, move their file into `Roster/Alumni/` and add `end_year` and `current_position`. Anyone in that folder is listed as a former member (e.g. `PhD` shows as "Former PhD Student"), so `role` doesn't need to change.
3. Optionally add a photo to `Roster/photos/` and set `photo: photos/firstname-lastname.jpg`.
4. Write the full bio below the front matter in Markdown.

> The field names `name`, `path`, `url`, `dir` and `content` are reserved by GitHub Pages. Use `title` for the person's name and `position` for their job title.

### Add a project
1. Copy the `Projects/template-project/` folder to `Projects/<short-name>/`.
2. Edit `info.md`. `status` is `On-going` or `Finished`. A `study_url` adds a **Take part** button while the project is on-going.
3. Add a 16:9 `cover.jpg` to the folder. If it is missing, a coloured placeholder is shown.

### Latest Substack posts
The Media page shows the 3 newest posts from https://christianwaugh.substack.com. A GitHub Action (`.github/workflows/substack.yml`) refreshes `data/substack.json` every day and commits only when there's a new post. To refresh right away, open the repository's **Actions** tab → *Update Substack posts* → **Run workflow**, or run `python3 scripts/update_substack.py` locally and commit the result. (Substack doesn't let other websites read its feed from the browser, which is why the posts are saved into the repository.)

### Publications, news, media
Edit `data/publications.yml`, `data/news.yml` and `data/media.yml`. Each file starts with a commented example of every field. Lab members' names are bolded in author lists automatically, based on the roster (`aliases:` in a roster file covers other spellings).

## Previewing locally

Run this from the repository root:

```bash
python3 -m http.server 8000
```

Then open http://localhost:8000. Opening the HTML files directly from disk (`file://`) won't work, because the pages load their content with `fetch`.

## How it works

- Pages are static HTML with a shared header and footer. Each page's script fills in the content.
- `data/*.yml` files are parsed in the browser with [js-yaml](https://github.com/nodeca/js-yaml); Markdown is rendered with [marked](https://marked.js.org).
- **Roster and Projects discovery:** a static site can't list folders, so on GitHub Pages the built-in Jekyll build writes `data/roster.json` and `data/projects.json` listing every Markdown file in `Roster/` and `Projects/`. During local preview those files are still raw templates, so the scripts read the folder listing from `python3 -m http.server` instead. Both paths produce the same result.

## Deployment

In the repository's **Settings → Pages**, set **Source** to *Deploy from a branch*, branch `main`, folder `/ (root)`.
